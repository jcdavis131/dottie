# Openswap — paid-SaaS replacement adapters

One adapter per paid platform, built on the Harper pattern: name the enemy,
make privacy architectural (no server, zero network calls — the manifest
denies the network axis, so the guarantee is falsifiable), let a local core do
real work day one, and detect-and-use the best native open binary when it
appears on PATH.

## Family contract (every adapter)

- **[A] detect_local_capability** — probe PATH for the native binary, confirm
  health with a cheap read-only subcommand, report
  `{tier: native|fallback|unavailable, native: {binary, found, path, version,
  probe_cmd, probe_output}}`.
- **[B] best_available_tier** — native binary when present → pure-stdlib
  fallback core (must self-describe its reduced scope) → explicit
  "unavailable" with an install hint. NEVER a silent no-op, NEVER a
  network/SaaS fallback tier.
- **[C] normalized diagnostics** — every tier emits
  `{path, line, col, rule, severity, message, suggestion, source}` with
  severity ∈ error|warning|suggestion|info.

**Shared base:** `bigbang/core/openswap.py` (`probe_binary`,
`capability_report`, `diagnostic`, `sort_diagnostics`, `summarize`,
`severity_rank`). Later adapters REUSE it — do not re-implement detection or
the schema. Each adapter follows the standard plugin recipe (see
`docs/EXTENDING.md`): pure logic in `bigbang/core/<name>.py`, real I/O in
`bigbang/plugins/<name>/cli.py`, default-deny manifest, then add a row here.
