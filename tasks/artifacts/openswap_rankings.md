## Provenance and honesty notes

- **Input truncation.** The three source lists were delivered truncated: org-usage visible through rank 19, feasibility through rank 17, market-value through rank 15. No full copies exist on disk (`Grep 'openswap|open_replacement|Grammarly'` over the repo: *No files found*). The visible union deduplicates to 28 distinct candidates; **ranks 29-50 are reconstructed tail entries** consistent with the org profile (8 static Vercel sites, one Windows box, factory/research loop, stdlib-only core + detect-and-use binaries) and carry **estimated** scores. Provenance column tags every row.
- **Imputed inputs.** Where a candidate is absent from a source list's visible portion, that dimension's score is imputed (marked `~`). Imputation uncertainty is roughly ±0.3 on a dimension, i.e. ±0.15 blended.
- **Environment claims re-verified 2026-07-23** (real command output):
  - `Get-Command harper` / `harper-cli` → `harper: NOT FOUND` / `harper-cli: NOT FOUND` — the stdlib fallback carries launch for rank 1.
  - `Test-Path C:\Users\jcdav\AppData\Local\Programs\Ollama\ollama.exe` → `True` — the ollama adapter's optional tier activates immediately.
  - repo venv `python -c "...fts5..."` → `fts5 OK 3.49.1` — FTS5 full-text search is zero-dependency today.

## Where the lists disagree (reconciliations)

1. **Uptime vs SEO auditor for the #2 slot.** OU ranks uptime #2 (9.8) and SEO #5 (9.2); MV ranks SEO #2 (Semrush ~$1,679/yr) and uptime only #15; FE scores both 9.5. Blended: SEO 9.37 vs uptime 9.32 — a gap smaller than the imputation uncertainty on uptime's truncated MV score, i.e. a statistical tie. The table keeps strict score order (SEO #2); the **build order puts uptime first** because its stdlib core is 100% of the product on day one, it is the org's single highest-frequency touchpoint (minutes-cadence over 8 sites + API + ollama endpoint), and its sqlite ledger + sched-loop daemon is the substrate that heartbeat (#6), cert (#9), status page (#18), and alert router (#19) reuse.
2. **SEO variants merged.** OU listed site-audit (#5) and meta/OG linter (#7) separately; FE listed crawler (#3) and Yoast on-page linter (#12); MV listed Semrush (#2) and Screaming Frog (#7). All are static-HTML assertions over the same crawl, so the authoritative list merges them into **one crawler-core adapter (rank 2)** with an audit-module architecture. This is what frees the top 10 from being 5 flavors of SEO.
3. **W&B run tracker promoted into the build-order top 10** over sitemap (8.53), article extractor (8.52), and RSS (8.51), despite scoring 8.40: its absence from OU's visible top-19 forces an imputed OU (~7.5) that the org's ledger-is-truth doctrine suggests is an underestimate; FE ranked it #6 at 9.5; and it adds a category (ML experiment tracking) the top 10 otherwise lacks, per the diversity requirement. Sitemap folds into the rank-2 crawler core anyway; extractor+RSS are one research-ingestion pipeline that ships together later.
4. **Ollama adapter.** Only MV ranked it in visible portions (#6, 8.8), but it is the sole adapter whose optional binary is **verified present today**; OU/FE imputed accordingly (~7.5 / ~8.8). It lands #17 — the stdlib-degraded core (template assembly) is genuinely weaker day-one than the adapters above it, which is what the "stdlib core useful on day one" preference measures.
